# npmctl command reference

Generated by `npmctl docs`. Do not edit by hand — regenerate instead, so this
file cannot drift from the binary.

Version: `dev`

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | generic error |
| 2 | usage error |
| 3 | refused, or needs a confirmation that was not given |
| 4 | auth failure (credentials rejected) |
| 5 | not found |
| 6 | NPM returned an error |
| 7 | network error — a mutating write MAY have applied |
| 8 | applied, but the nginx reload failed |
| 9 | interactive re-authentication required |

## Write gate

Every mutation requires **both** `NPMCTL_ALLOW_WRITE=1` in the environment and
`--yes` on the command line. `--dry-run` previews any mutation and issues no
mutating request.

| Tier | Additional requirement |
|---|---|
| normal | none beyond the two factors |
| destructive | a dependency scan, plus `--cascade-ack` when dependents exist |
| privileged | an interactive terminal and a typed confirmation |

## Global flags

| Flag | Default | Description |
|---|---|---|
| `--allow-advanced-config` | `false` | permit writing raw nginx directives via advanced_config |
| `--ca-cert` | `—` | PEM bundle trusted for this instance — solves self-signed without --insecure |
| `--cascade-ack` | `false` | acknowledge that dependent objects will be affected by a delete |
| `--config` | `—` | path to config.yaml |
| `--dry-run` | `false` | preview a mutation; issues no mutating request |
| `--force` | `false` | override a non-safety guard (e.g. the certificate attempt cooldown) |
| `--insecure` | `—` | skip TLS verification (true/false); prefer --ca-cert or --pin-sha256 |
| `-o`, `--output` | `—` | output format: table, json or yaml (default: table on a terminal, json when piped) |
| `--pin-sha256` | `—` | expected SHA-256 of the server's public key |
| `-p`, `--profile` | `—` | profile to use (default: configured default_profile) |
| `--timeout` | `30s` | per-request timeout |
| `--token` | `—` | bearer token to use for this call only (never persisted) |
| `--url` | `—` | NPM base URL, overriding the profile |
| `-v`, `--verbose` | `false` | log HTTP requests to stderr (secrets are redacted) |
| `--yes` | `false` | confirm a mutation (also requires NPMCTL_ALLOW_WRITE=1) |

## Commands

### `acl`

Manage access lists

```text
Access lists combine HTTP basic auth with IP allow/deny rules.

IMPORTANT: `acl update` REPLACES the items and clients arrays wholesale — it does
not merge. NPM never returns existing passwords (it returns an empty string), so
npmctl cannot reconstruct them for you. You must pass every user you want to keep,
with their password. Any user you omit is removed.

Use --dry-run to see exactly which users would be added, removed, or have their
password reset before anything is written.
```

#### `acl create`

Create an access list

**Write** — tier: normal. Requires `NPMCTL_ALLOW_WRITE=1` and `--yes`.

Usage: `npmctl acl create [flags]`

| Flag | Default | Description |
|---|---|---|
| `--client` | `[]` | IP rule as directive:address, e.g. allow:192.168.0.0/24 (repeatable) |
| `--item` | `[]` | basic-auth user as username:password (repeatable) |
| `--name` | `—` | access list name |
| `--pass-auth` | `false` | forward the Authorization header upstream |
| `--satisfy-any` | `false` | pass if ANY rule matches (default: ALL must match) |

#### `acl get`

Show one access list

Usage: `npmctl acl get <id|name>`

#### `acl list`

List access lists

Usage: `npmctl acl list`

#### `acl rm`

Delete an access list

**Write** — tier: destructive. Requires `NPMCTL_ALLOW_WRITE=1` and `--yes`.

Usage: `npmctl acl rm <id|name>`

#### `acl update`

Update an access list (items and clients are REPLACED, not merged)

**Write** — tier: normal. Requires `NPMCTL_ALLOW_WRITE=1` and `--yes`.

```text
Replaces the fields you pass. --item and --client replace their arrays entirely:
every user you want to keep must be listed with its password, because NPM never
returns existing passwords and npmctl will not invent them.

Run with --dry-run first to see the ADDED / REMOVED / PASSWORD RESET breakdown.
```

Usage: `npmctl acl update <id|name> [flags]`

| Flag | Default | Description |
|---|---|---|

### `cert`

Manage SSL certificates

```text
Manage the certificates NPM holds, including Let's Encrypt orders.

WARNING: `cert rm` on a Let's Encrypt certificate REVOKES it with the certificate
authority. That is irreversible — the undo journal can restore the database row,
but not the certificate material.

Let's Encrypt allows 5 duplicate certificates per week. npmctl tracks issuance
attempts per domain set and refuses a 4th attempt inside 7 days; it never retries
an order automatically.
```

#### `cert create`

Request a certificate

**Write** — tier: normal. Requires `NPMCTL_ALLOW_WRITE=1` and `--yes`.

```text
Requests a certificate from NPM. For provider=letsencrypt this runs a real ACME
order, which counts against Let's Encrypt's limit of 5 duplicate certificates per
week.

npmctl records every attempt per domain set and refuses a 4th inside 7 days
(--force overrides). It never retries automatically: a failed order is reported,
not repeated.

--wait (default) polls until the outcome is certain and reports exactly one of
ISSUED, NOT PRESENT, or INDETERMINATE.
```

Usage: `npmctl cert create [flags]`

| Flag | Default | Description |
|---|---|---|
| `--dns-challenge` | `false` | use the DNS-01 challenge instead of HTTP-01 |
| `--dns-credentials` | `—` | DNS-01 provider credentials (never echoed) |
| `--dns-provider` | `—` | DNS-01 provider name (see `npmctl cert dns-providers`) |
| `--domain` | `[]` | domain to certify (repeatable) |
| `--key-type` | `—` | key type: rsa or ecdsa |
| `--name` | `—` | display name (defaults to the first domain) |
| `--propagation-seconds` | `0` | DNS propagation wait before validation |
| `--provider` | `letsencrypt` | certificate provider: letsencrypt or other |
| `--timeout` | `0s` | override the issuance deadline |
| `--wait` | `true` | poll until the outcome is certain |

#### `cert dns-providers`

List supported DNS-01 providers

Usage: `npmctl cert dns-providers`

### `schema`

Fetch and compare the NPM API schema

```text
npmctl is written against the Nginx Proxy Manager 2.15.1 OpenAPI document, vendored
as a test fixture rather than used to generate code.

`schema check` compares a live instance against that copy so an upgrade that changes
a request shape is caught deliberately, instead of surfacing as a puzzling 400.

It cannot detect BEHAVIOURAL drift — partial-update semantics, the TLS flag coercion
cascade, revoke-on-delete — because no schema expresses those. The lab instance and
the opt-in E2E tests cover that gap.
```

#### `schema check`

Compare a schema against the vendored 2.15.1 copy

```text
Exits 0 when the schemas are equivalent, 1 when an implemented path has drifted.

Drift confined to paths v1 does not implement (the /users family, PUT /settings/{id})
is reported as informational and does not fail: it cannot break this binary.
```

Usage: `npmctl schema check [flags]`

| Flag | Default | Description |
|---|---|---|
| `--from-file` | `—` | compare against a schema file instead of a live instance |
| `--vendored` | `—` | path to the vendored schema (default: the embedded copy) |

#### `schema get`

Fetch the live instance's OpenAPI document

Usage: `npmctl schema get`

### `undo`

Inspect and replay pre-images captured before each write

```text
npmctl records the prior state of every object it mutates, before mutating it.

`undo list` and `undo show` are reads. `undo apply` is a WRITE: it replays the
pre-image through the same gate as any other mutation.

Entries are stored unredacted at mode 0600 and swept after 30 days — a redacted
pre-image could not be restored. Treat the directory as sensitive.
```

#### `undo apply`

Replay a pre-image as a write (gated like any other mutation)

**Write** — tier: privileged. Requires `NPMCTL_ALLOW_WRITE=1` and `--yes`.

Usage: `npmctl undo apply <entry>`

#### `undo list`

List captured pre-images for the active profile, newest first

Usage: `npmctl undo list`

#### `undo show`

Render a captured pre-image (redacted for display)

Usage: `npmctl undo show <entry>`
